### F16 · 默认六体配合正常滑块参数，约0.32秒后物理页签失效，重置按钮也不能恢复 — P1

### F17 · 无摩擦多点碰撞“动能守恒但响应错误”：求解结束时仍向对方穿入 — P1

**位置：** `js/collide4.js:271`；`js/physics4.js:344–363`；漏测在 `test/collide4.test.js:317–353`。

所有接触都被设置 `target=−e·vn_before`，包括初始正在分离的接触，所以目标可以为负。多点耦合把这样的接触变成接近后，只要 `vn_after≥target`，求解器仍认为满足约束。μ=0时又跳过后面的零目标支撑阶段。

**独立确认：** 两个默认盒子精确共面，初始穿透为0；下方速度是手写分量式，不调用被测的接触速度函数：

```sh
node <<'NODE'
global.window=global;
for(const f of ['m4','physics4','collide4']) require('./js/'+f+'.js');
const a=new RigidBody4({angularVelocity:[1,0,0,-1,-1,0]});
const b=new RigidBody4({position:[0,1.2,0,0]});
const hit=Collide4.collide(a,b),p=[-.6,.6,-.6,-.6];
function vy(o){
  const r=p.map((x,i)=>x-o.position[i]),w=o.angularVelocity;
  return o.velocity[1]+w[0]*r[0]-w[3]*r[2]-w[4]*r[3];
}
console.log('depth/before',hit.depth,vy(b)-vy(a));
console.log(Physics4.solveContacts(Collide4.pairContacts(a,b,hit,1),0,2048));
console.log('after/energy',vy(b)-vy(a),a.kineticEnergy()+b.kineticEnergy());
a.step(1e-6,0);b.step(1e-6,0);
console.log('next penetration',Collide4.sat(a,b).depth);
NODE
```

实测：相对法向速度从 **+1.8变成−0.490909…**；求解5轮、`change=0`，动能仍为.36。再推进1e−6即穿透约 `4.90909e-7`。这是精确共面时的瞬时响应，不是深穿透位置投影或流形近似解释得掉的误差。

实际默认六体e=1/μ=0也在约.621秒出现碰后 `vn≈−.641831` 的接触。把最小例的μ从0改成1e−20，额外法向支撑阶段突然启用，总动能从.36降至约.349046、最小vn回到约0；这种不连续不是无限小摩擦应有的无限小切向效果。

**建议：** 明确多点冲击与非穿透的自洽策略，验证所有活动接触的碰后速度，而不只验证动量/动能。修改目标后要一起重审恢复系数和能量推导，不能夹一下速度再沿用旧证明，或事后缩放能量掩盖问题。

### F01 · “等倾双旋转”按钮通常没有产生等倾运动 — P1

**位置：** `js/app.js:162–172`；`js/view-projection.js:56–70`；声明在 `README.md:42–48`、`index.html:273–274`。

**独立确认：** 投影页先让默认自转运行约三秒，再按等倾按钮。比较同一小段运动前后四个单位基向量的夹角，等倾运动要求四个余弦相同，而实际不同：

```sh

for (const f of ['m4','polytopes','view-projection']) require('./js/'+f+'.js');
const v = new ProjectionView({getContext:()=>({}),addEventListener(){}});
v.step(3);
v.speeds = {xy:.4,zw:.4,xz:0,yz:0,xw:0,yw:0};
const a = v.rotor(); v.step(.5); const b = v.rotor();
console.log([0,1,2,3].map(i => M4.dot(M4.col(a,i),M4.col(b,i))));
NODE
```

实测为 `[0.989328271669035, 0.9800665778412416, 0.9776285737528914, 0.9734275053547732]`。这不是像素或颜色判断。只有旧姿态恰好合适时，按钮才碰巧符合声明。

**建议：** 从既有姿态施加一个固定的等倾增量，或明确复位全部角度后开始演示；检查 `R(t+dt)R(t)ᵀ` 的等倾性质，而不只检查滑块值。

### F07 · 已在研究里纠正的旋转与投影错误，仍出现在主入口 — P2

**位置：** `README.md:11–16,25,44,69,77`；`index.html:223–225,268–274`；`js/m4.js:6–9,115`。

这里至少有五个不同的错误/过强表述：

1. “四维旋转有一个不动平面”只适用于简单旋转；一般双旋转没有非零固定向量。
2. “没有任何一个点静止”遗漏了原点，以及转角为整周的情形。
3. 正交投影“形状不失真”错误：它能把长度2的线段压成点。
4. 投影“保留完整拓扑结构”错误：物体可以重影、相交、降秩，非嵌入投影不保拓扑。
5. “必须降两次维”“画 Hopf/Clifford 必须用立体投影”把设计选择说成数学必要条件；直接取 `(x,y)` 就是一次 4→2 映射，Hopf 圆也可以作其他投影，只是效果不同。

**独立确认：** `R=Rxy(π/2)Rzw(π/2)` 的 `det(R−I)=4`，无非零固定向量；而 `[0,0,0,±1]` 两点经过实际 `M4.ortho4to3` 都得到 `[0,0,0,1]`。这也直接否定无损尺寸与保拓扑。`docs/intuition-research.md:55–58`、`docs/math/representations.md:186–187` 已给出正确限定，故不是审查者与仓库采用不同数学约定。

**建议：** 同步修正文案/注释，而不是只在深层研究文档里纠错。保留“这是本项目选择的流水线”和“简单旋转”的限定。

### F08 · 双圆柱不能切成带洞的圆环；只扫 w 也不会把球环面的球壳变成环面 — P2

**位置：** `README.md:171–179`；`index.html:328–329`；实现为 `js/scene4.js:21–26,232–233`。

`duocylinder` 是两个**实心圆盘的笛卡尔积**，是凸集。任何仿射超平面截面仍然凸，不可能出现环形空洞。固定 w 的截面具体为圆盘乘线段，即实心圆柱，直到退化/消失。

球环面没有同样的凸性限制，但按页面最先教的 Q/E 保持朝向扫 w 时，截面满足：

```text
R − sqrt(r²−w²) ≤ |xyz−center.xyz| ≤ R + sqrt(r²−w²)
```

所以 `|w|<r` 时仍为同心球壳，等号时退化，超过后为空。**倾斜切面**才可能得到环面；不能把两种操作混写。

**独立确认：** 直接从当前两条 SDF 的 `f≤0` 解不等式；球环面实际 `R=1.15,r=.45`，w=0 的径向区间为 `[.7,1.6]`，w=.44 为约 `[1.05566,1.24434]`，一直没有变成环面。这是解析反证，不依赖渲染分辨率。

**建议：** 双圆柱改成“凸截面/圆柱退化”的真实教学点；球环面明确给出转身方向与角度，区分 w 平移和改变 H。给文案中的拓扑变化增加针对性几何测试。

### 数学/几何不是一片空白
