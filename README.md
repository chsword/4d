# 在浏览器里展示四维空间

第四个维度是**空间维**（记作 w），不是时间。目标是让人真的「看见」四维，而不是看一段动画。

打开 `index.html` 即可 —— 零依赖、零构建、`file://` 直接双击能跑。前三个页签对应三条技术路线，第四个是四维刚体物理沙盒。

---

## 一、核心难题

屏幕是二维的，所以从 4D 到屏幕必须降两次维。降维必然丢信息，问题只是**丢哪部分**：

| 做法 | 丢掉的是 | 留下的是 | 代价 |
|---|---|---|---|
| **投影** 4D→3D→2D | 尺寸、角度 | 完整的拓扑结构 | 严重形变，看起来「不真实」 |
| **切片** 只取一个 3D 超平面 | 超平面外的一切 | 100% 真实的局部几何 | 一次只看到一层 |
| **编码** 把 w 映射到颜色/大小/时间 | 精确的空间关系 | 定量可读 | 不产生空间直觉 |

没有哪一种单独够用。真正有效的方案是**投影看全貌 + 切片建直觉 + 编码补细节**，这也是本仓库三个视图的分工。

## 二、四维旋转：和 3D 最不一样的地方

**3D 的旋转有一根不动的轴；4D 的旋转有一个不动的平面。**

四个坐标轴两两配对，得到 6 个旋转平面，所以 SO(4) 有 6 个自由度（SO(3) 只有 3 个）。每个平面对应一个 Givens 旋转矩阵 —— 对平面 (i, j)：

```
M[i][i] =  cos θ    M[i][j] = -sin θ
M[j][i] =  sin θ    M[j][j] =  cos θ
其余为单位矩阵
```

实现见 `js/m4.js` 的 `rotation(plane, angle)`。

把 6 个平面分成两组，是理解四维旋转的关键：

- **xy / xz / yz** —— 不动的平面里含有 w 轴，所以 w 坐标全程不变。这是我们熟悉的「普通 3D 旋转」，投影图上看不出任何异样。
- **xw / yw / zw** —— 把第四维搅进来。只有这三个会让形状看起来**从自己内部翻出来**。想看四维，只需要动这三个滑块。

还有一个 3D 里根本不存在的现象：**等倾双旋转（isoclinic rotation）**。两个互相垂直的平面（比如 xy 和 zw）以同一角速度转动，此时：

- 没有任何一个点是静止的（3D 旋转必有不动轴，上面的点不动）；
- 空间里每一个向量都以同一角度转过；
- 四元数乘法就是这件事 —— 左乘单位四元数 = S³ 上的一个等倾旋转。

`index.html` 投影页签的「等倾双旋转」按钮就是这个。

⚠️ **4D 旋转不交换**，合成 6 个平面时的顺序会影响结果。代码里固定了一个顺序，只求视觉连续，没有物理含义。

⚠️ 另外：连乘几万次旋转矩阵会有浮点漂移，形状会慢慢被剪切变形。`m4.js` 的 `orthonormalize()` 每帧对列做一次 Gram-Schmidt。实测 10 万次累乘后偏离正交约 `3e-12`，收一次归零。

## 三、手法 A：投影（`js/view-projection.js`）

### 4D → 3D

**透视投影**。观察者站在第四维上的 `(0,0,0,d)`：

```js
k = d / (d - w)
(x, y, z) → (x·k, y·k, z·k)
```

这就是超立方体那张「盒中盒」经典图的来源 —— 内层那个小立方体并没有更小，它只是在第四维上离我们更远。`d` 越接近物体（滑块调到 1.3 附近），透视越夸张。

**正交投影**：直接丢掉 w。形状不失真，但会大量自我重叠。

**立体投影（stereographic）**：只对 S³ 上的点有定义，从北极投影到 `w=0` 超平面。

```js
(x, y, z) → (x, y, z) / (1 - w)
```

它保角（共形），画 Hopf 纤维化和 Clifford 环面必须用它。注意 `w → 1` 时会放大到十几倍，代码里做了归一化 + 缩放 + 长棱剔除，否则个别棱会被拉成横穿全屏的直线。

### 3D → 2D

普通的可拖动透视相机。**两级投影必须让用户分别控制** —— 否则人分不清「形状在变」和「我在转」。

### 感知技巧（真正决定能不能看懂）

1. **色相编码 w**：暖色 = w 大，冷色 = w 小。没有这个，线框就是一团面条。
2. **线宽随 w 变化**：给一个第二重冗余线索。
3. **按深度排序后绘制**，近处的线更亮更实。
4. **一次只动一个平面**。同时转 6 个平面等于什么都没展示。

### 图形清单

正则四维多胞体一共只有 6 个（3D 是 5 个柏拉图立体）。代码实现了前四个：

| 图形 | 顶点/棱 | 说明 |
|---|---|---|
| 5-cell 单纯形 | 5 / 10 | 四面体的四维版，最简单的四维体 |
| 8-cell 超立方体 | 16 / 32 | 8 个立方体胞，24 个正方形面 |
| 16-cell | 8 / 24 | 超立方体的对偶 |
| 24-cell | 24 / 96 | **四维独有**，3D 里没有任何类比，且自对偶 |
| 6×6 双棱柱 | 36 / 72 | 两个六边形的笛卡尔积；xy 转一个圈、zw 转另一个，互不干扰 |
| Clifford 环面 | — | 把 S³ 干净地分成两个全等实心环 |
| Hopf 纤维化 | — | S² 上每个点对应 S³ 里一整个圆，投影后两两套扣却永不相交 |

120-cell（600 顶点 / 1200 棱）和 600-cell 没做：线框画出来只是一团毛球，教学价值反而低于 24-cell。

棱表是自动生成的 —— 取所有「距离最短的顶点对」。正则多胞体的最短顶点间距就是棱长，省掉手写棱表。见 `polytopes.js:edgesByNearest`。

## 四、手法 B：切片（`js/view-slice.js`）—— 这条路才能「住进去」

### 原理

思路完全照搬《平面国》：二维生物看不到球，只能看到球与它所在平面的交 —— 一个会长大又缩小的圆。每个词加一维：

> 我们看不到四维物体，只能看到它与我们所在的那个**三维超平面**的交。

### 渲染管线

1. 玩家在 4D 里有位置 `uCam` 和一组正交基 `(Ax, Ay, Az, Aw)`。前三个张成「我们能看见的那个三维世界」，**`Aw` 指向我们看不见的方向**。
2. 在这个三维切片里做普通的 ray marching。屏幕每个像素发一条射线，射线上的三维点 `q` 先抬回四维：

   ```glsl
   vec4 lift(vec3 q){ return uCam + q.x*uAx + q.y*uAy + q.z*uAz; }
   ```

   然后求**四维**有向距离场 `map(lift(q))`。
3. 法线取 `map` 在 `Ax / Ay / Az` 三个方向上的差分 —— 得到的是**切片内**的法线，也就是切片里的居民真正会看到的明暗。

这套做法的漂亮之处：整个四维场景只需要一个 4D SDF 函数，剩下全是标准的三维 ray marching。**没有任何形变，看到的是百分之百真实的局部几何。** Miegakure、4D Toys、4D Golf 走的都是这条路。

### 常用 4D SDF 原语

```glsl
float sdSphere4(vec4 p, float r){ return length(p) - r; }             // glome 超球

float sdBox4(vec4 p, vec4 b){                                         // 四维盒子
  vec4 d = abs(p) - b;
  return length(max(d, 0.0)) + min(max(max(d.x,d.y), max(d.z,d.w)), 0.0);
}

float sdDuocylinder(vec4 p, float r1, float r2){                      // 双圆柱：四维独有
  vec2 d = vec2(length(p.xy) - r1, length(p.zw) - r2);
  return min(max(d.x, d.y), 0.0) + length(max(d, 0.0));
}

float sdSpheritorus(vec4 p, float R, float r){                        // 球环面
  return length(vec2(length(p.xyz) - R, p.w)) - r;
}

float sdTiger(vec4 p, float R1, float R2, float r){                    // 切片会分裂成两个环
  return length(vec2(length(p.xy) - R1, length(p.zw) - R2)) - r;
}
```

注意 `sdBox4` 就是 3D 版本逐字加一维 —— 大部分 SDF 都是这样平移过去的，这也是 SDF 比多边形网格适合四维的原因（4D 三角网格要处理 5-cell 单纯形和四维凸包，工程量高一个量级）。

### 让人不迷失的三个设计

一次只看一层，人极易失去方向感。三个必要的锚点：

1. **地板棋盘格的第三个因子取 `floor(w)`** —— 沿第四维移动时格子会翻色。这是「我确实动了」最直接的反馈，没有它玩家会怀疑按键失灵。
2. **贯穿所有 w 的柱子** —— 提供「这个方向确实没变」的参照物。
3. **把 4D 旋转限制在不含 y 的平面（xw / zw）** —— 地板法线 `(0,1,0,0)` 在这两个旋转下不变，所以地板在切片里永远是一个正常的水平面。若允许 yw 旋转，重力方向会在切片里倾斜，人会立刻晕。

### 两个额外的可视化开关

- **第四维厚度染色**：命中点沿 `Aw` 正反各探 10 步，数有多少步还在物体内部。薄得像纸（马上要消失）的表面染红 —— 提前告诉你「再按一下 E 它就没了」。
- **X 光**：射线在第四维上左右各偏 `1.1` 再测一次距离，把「隔壁切片里有东西」画成蓝雾。隐藏物体会先以雾的形式出现。

### 场景里安排的教学点

| 物体 | 在第四维上的范围 | 现象 |
|---|---|---|
| glome 超球 | 全部 | 切片永远是球，半径随 w 变 → **凭空出现、长大、缩小、消失** |
| 超立方体 | w ∈ [−1, 1] | 切片是恒定的立方体，然后突然整体消失 |
| 双圆柱 | — | 切片在圆柱和圆环之间连续变形 |
| 球环面 | — | 切片从球壳裂开成环面 |
| tiger | — | 切片**分裂成两个独立的环** |
| 灰墙 | \|w\| < 1.6 | 挡住路 |
| 金色方块 | w ≈ 3 | 墙后面，只在那一层存在 |
| 柱子 | 全部 | 参照物 |

**核心体验**：往前走撞到灰墙 → 按 `E` 把 w 推到 3 → 墙整个消失 → 直接走过去 → 看到金色方块。

这不是穿墙外挂，是四维生物看三维牢房的真实体验：**那间牢房根本没有第四面墙。** 三维监狱对四维生物完全无效，这一点在纸上读到和自己走一遍，理解深度差一个量级。

### 操作

| 键 | 作用 |
|---|---|
| 点击画面 | 锁定鼠标，之后移动鼠标转头 |
| `W A S D` | 在三维里走 |
| `Space` / `C` | 上 / 下 |
| **`Q` / `E`** | **沿第四维平移（kata / ana）** |
| `Z` / `X` | zw 平面转身：把「前」转向第四维 |
| `R` / `F` | xw 平面转身：把「右」转向第四维 |
| `Shift` | 加速 |
| `Esc` | 解锁鼠标 |

`Q`/`E` 是**平移**，切片保持平行只是滑过去；`Z`/`X`/`R`/`F` 是**转身**，换的是整个视网膜所在的那张超平面 —— 物体会以三维里不可能的方式变形。两者感觉完全不同，值得分别体会。

## 五、手法 C：降维类比（`js/view-analogy.js`）

人对四维没有直觉，对三维有。所以最有效的教法是**先把同一套操作在低一维上做一遍**。四块面板：

- **A** 我们的视角：立方体全貌 + 那张切割平面（我们看得见全貌）
- **B** 平面人的视角：他只看到那个多边形 —— 边数会从 3 跳到 4、5、6 再跳回去，他会说「这东西在变形」，但立方体什么都没变
- **C** 同一个操作升一维：超立方体 ∩ 超平面 `w=k` → 一个三维多面体
- **D** 胶片：k 连续变化时截面这一串形状。**所谓「一个四维物体」，对我们来说就是这一整排三维形状的全体。**

### 多胞体截面算法

比 marching cubes 简单得多，而且是精确的：

> 用超平面去切每一个**二维面**。每个凸多边形面被超平面切出恰好一条线段，把所有线段拼起来就是截面的线框。

实现见 `view-analogy.js:sliceFaces`，对任意维度、任意「顶点 + 二维面」结构都适用。面表也是自动生成的：一个正方形面 = 挑 2 个轴自由变动、另 2 个轴取定值，所以超立方体有 C(4,2)×4 = 24 个正方形面。

已验证的结果：

| 切法 | 得到 |
|---|---|
| 立方体 ∩ `y=0.5` | 正方形（4 条边）|
| 立方体（体对角线竖直）∩ `y=0` | **正六边形**（6 条边）|
| 超立方体 ∩ `w=0` | 立方体（12 条棱）|
| 超立方体 ∩ `w=2` | 空（整个在超平面之外）|
| 超立方体斜切 | 15 棱 / 10 顶点 / 全部度数 3 → 五棱柱拓扑 |

## 六、技术栈怎么选

| 方案 | 适合 | 不适合 |
|---|---|---|
| **Canvas 2D** | 线框投影。几百条棱轻松跑满 60fps，深度排序、色相编码、线宽全都好控制 | 实体表面 |
| **WebGL fragment shader + 4D SDF raymarching** | 切片法。**强烈推荐** —— 一个 SDF 函数搞定整个四维场景，不需要任何网格数据结构 | 大规模场景（SDF 不好做剔除）|
| **three.js + 自写 4D 层** | 想要 PBR、阴影贴图、后处理，或者要和已有 3D 项目整合 | 只做线框时纯属过度设计 |
| **4D marching cubes / 5-cell 网格** | 需要把切片导出成真实 mesh（比如导出 STL 打印）| 实时渲染。每帧重建网格，不如直接 raymarch |

本仓库选了 Canvas 2D（类比、投影）+ 裸 WebGL（切片、物理），因为要保证**零依赖 + `file://` 双击可跑**。所以 JS 都用传统 `<script>` 标签而非 ES module —— `file://` 下 ES module 会被 CORS 拦住。

### 两个容易踩的坑

1. **GLSL 源码必须是纯 ASCII。** GLSL ES 规定的字符集不含中文，ANGLE 等实现会连**注释里**的非 ASCII 字符一起报错。所以 `view-slice.js` 把着色器的中文说明全搬到了 JS 注释里。
2. **不要对向量用三目运算符**（`cond ? vecA : vecB`）。规范允许，但部分老驱动编译不过。写成 `if` 返回。

### 性能

切片与物理视图是逐像素 ray marching，每像素要求几十次四维距离场。按 `devicePixelRatio` 全分辨率渲染在集显上会掉到个位数帧率，所以 `app.js` 给它们设了 `Math.min(dpr, 1)`；线框那两个视图是 Canvas 2D，反而需要高 dpr 才不毛糙。如果还是卡，降 `FRAG` 里的 raymarch 步数（128）和软阴影步数（28）。

## 七、四维刚体物理（`js/physics4.js`、`js/view-physics.js`）

### 为什么角速度不再是向量

任意维度的角速度实际都是反对称矩阵 Ω，或等价的 **bivector（二重向量）**。
三维恰好 C(3,2)=3，可以通过 Hodge 对偶写成「转轴向量」；四维 C(4,2)=6，不能再用一个四维向量冒充。
本实现和 `M4.PLANES` 统一使用 **`[xy, xz, xw, yz, yw, zw]`**，每个分量对应一个旋转平面，而不是一根转轴。
原来的平面表将 yz 放在 xw 前面，这里已统一；现有投影动画仍保留自身的合成顺序，函数签名没有改变。

正 xy 分量把 +x 转向 +y，和 `M4.rotation('xy', angle)` 同号：

```
Ω[i,j] = -ω_ij，Ω[j,i] = ω_ij
(a ∧ b)_ij = a_i b_j - a_j b_i
τ = r ∧ F，v_contact = v_center + Ω_world r
```

这个约定满足 `〈r∧F, ω〉 = F·(Ωr)`，保证转动能、力矩与接触冲量的符号一致。
姿态 R 把本体系送到世界系；bivector 的换系是 `B_world = R B_body Rᵀ`，
**不是**把它当成四维向量乘一次 R。`Physics4.dot6` 是六分量内积，不能用只读四分量的 `M4.dot` 代替。

### 6×6 惯性张量从哪里来

把 `T_rot = ½∫|Ωr|² dm` 展开成关于六个 ω 分量的二次型，得到 `T_rot = ½ωᵀIω`。
I 把 bivector 映到 bivector，因此是 **6×6 对称正定矩阵**。实现支持完整的行主序 36 元素矩阵，
通过 Cholesky 验证正定性并求逆；对齐主方向的两种均匀实心形状有简单解析式：

| 形状 | 二阶矩 | 每个平面 ij 的对角惯性 |
|---|---|---|
| box4，半边长 h | `〈r_i²〉 = h_i²/3` | `m(h_i²+h_j²)/3` |
| glome，半径 a | n 维实心球 `〈r_i²〉 = a²/(n+2)` | n=4 时 `ma²/3` |

交叉二阶矩为零，所以这些主平面基底下非对角项为零。这里的 glome 是**实心四维球**，
不是 S³ 球壳，也不能套三维球的 `2ma²/5`。盒子的 `h_w=0` 可用于三维退化检验。

### 欧拉方程与时间积分

世界系角动量满足 `dL_world/dt = τ_world`。对 `L_body = Rᵀ L_world R` 求导，
结合 `R' = RΩ`，得到

```
I · dω_body/dt = τ_body - [Ω, L_body]
[Ω, L] = ΩL - LΩ
```

无外力矩时，世界系 L 不变，但本体系 ω 通常不断改变，这就是自由刚体的 tumbling。
**并非只有等倾运动才有恒定 ω**：等方惯性（例如 glome）、单主平面旋转等也可以；
关键条件是 `[Ω,Iω]=0`。

平移采用**半隐式欧拉**（先更新速度，再用新速度更新位置），重力沿 −y。
转动先 kick 世界角动量，再以固定的世界 L 积分 `R'=RΩ(RᵀL_world R)`：
使用 RK4，并在每个姿态子步调用 `M4.orthonormalize`，最后从新姿态重新求本体系 ω。
这里刻意没有用裸 Euler 更新 ω：它会持续积累转动能误差，无法满足长时间守恒要求。
世界 L 的保持来自坐标变换恒等式；能量是四阶数值近似守恒，**不做事后能量缩放或自由运动阻尼**。
单步估计转角超过 0.05 弧度时细分姿态积分。外力和外力矩在每个物理步之后清空。

### 地板接触与冲量

地板是 `y = -1.5` 的无限超平面。box4 枚举 16 个顶点，最深穿透量用于直接投影修正；
同时保留接触顶点做多点支撑，避免把平放盒子当成单个角点支撑。glome 用中心到地板的距离。
法向冲量的有效逆质量包含完整的角向项：

```
k(n) = 1/m + n · [I_world⁻¹(r ∧ n)] r
j_n = -(1+e) v_contact·n / k(n)
Δv = J/m，Δω_body = I_body⁻¹[(Rᵀr) ∧ (RᵀJ)]
```

方括号内先得到 bivector，再转成反对称矩阵作用到 r。三维退化时就是熟悉的叉积有效质量公式。
地板的切空间有 x/z/w **三个**方向：摩擦沿接触点滑动速度反向，并限制在 `|J_t| ≤ μJ_n` 的库仑锥内。
反弹逐点处理；随后做至多 32 轮累计支撑/摩擦冲量迭代，允许撤回过量支撑。
法向接近速度小于 0.5 时不触发恢复反弹，以免静止物体因每一步重力 kick 微跳。
位置修正与速度求解分开，不把穿透深度变成额外弹射速度。
对步首悬空、步末穿透的情况，在半隐式轨迹上二分首次检测到的落地过零并拆分该时间步，
避免完全弹性落体因整步穿透后抬高位置而越弹越高；外力在拆分的两段中按各自时长施加。

### 沙盒、接口和边界

`PhysicsView` 只向 `SliceView` 注入动态场景 SDF 和 uniforms；共享相机、法线、光照、雾、厚度染色、

  切换页签清空按键、暂停该场景，避免卡键或回到页面后补算大量时间。

## 八、四维两两碰撞（`js/collide4.js`）

### GJK 如何升到四维

支撑函数仍是 `s(d) = argmax x·d`。box4 先把 d 乘 Rᵀ，本体系取 `sign(d_i) h_i`，
再乘 R 加质心；glome 返回 `x + radius·d/|d|`。Minkowski 差的支撑点是 `s_A(d)-s_B(-d)`，
每个点同时保存 A、B 的原始支撑点，用重心坐标还原最近点对。
`Collide4.gjk(a,b)` 返回 `{ intersects, distance, pointA, pointB, iterations }`，
也接受提供世界系 `support(direction)` 的任意凸体，不依赖 SAT 或形状专用回退。

四维单纯形最多 **5 点**。最近点例程枚举全部非空子面，最多 31 个，包括 5 个四面体边界胞；
对每个仿射子空间求原点投影，检查重心坐标非负，再选最近的可行面。
这里没有照搬 Johnson，也没有采用 signed-volume 的行列式比值：
选择**二次正交化 QR**，避免 Gram 行列式平方条件数，便于处理降维、共面和长宽比很大的单纯形。
这是常数规模的穷举，不是对形状顶点穷举。近接触时，再消除投影中的切向消减误差，
否则一个约 `1e-16` 的切向残差就可能阻止距离约 `1e-6` 的 GJK 收敛。
距离上、下界之差作为终止条件，尺度相关容差为 `1e-10`；迭代超过 256 次明确报错，不返回假成功。

**GJK 不返回穿透深度。** 零距离只有相交/接触信息，没有 MTV。
因此验证深度时，把 B 沿 SAT 法向分别平移 `depth`、`depth−2e-6`、`depth+2e-6`：
独立 GJK 必须分别报告接触、仍相交、分离且距离为 `2e-6`。
这不是将 SAT 深度回填到 GJK 再比较同一个数。

### 为什么盒子用 SAT，不用四维 EPA

四维 EPA 的边界是**四面体胞**，新顶点的 horizon 是**三角形集合**，
需要维护闭合的三维边界复形；把三维 EPA 的三角形列表直接升维是不正确的。
盒子有更简单而精确的特例：n 维盒子的 Minkowski 差是 zonotope，候选胞法向
由 A、B 棱方向中取 n−1 个张成的超平面得到。四维的候选数为：

| 棱方向组合 | 数量 |
|---|---:|
| 3A：A 自身的胞法向 | 4 |
| 3B：B 自身的胞法向 | 4 |
| 2A+1B | C(4,2)×4 = 24 |
| 1A+2B | 4×C(4,2) = 24 |
| 合计 | **56** |

三个方向的广义叉积为 `n_i = (−1)^i det(删掉第 i 列的 3×3 子阵)`。
忽略线性相关的零轴，其余归一化后，投影半径为 `Σ h_i |R_i·n|`。
任意轴分离就无接触；否则最小的 `r_A+r_B−|(x_B−x_A)·n|` 是精确 MTV 深度，
也正确处理一个盒子完全包含另一个盒子。三维退化时保留 xyz 的胞法向和交叉轴，
相交结论与 15 轴 3D SAT 一致；共同的零厚度 w 轴意味着 **4D 穿透深度为零**，
不能要求它也等于三维内部的穿透深度。

glome/glome 用球心距离；glome/box4 把球心送到盒子本体系逐坐标 clamp。
球心在盒内时，选择最近出口胞面，深度为到该面的距离**加**球半径，而非简单返回半径。

### 接触流形与共同作用点

`Collide4.collide(a,b)` 无接触时返回 `null`，否则返回 `{ normal, depth, points }`。
**normal 从 A 指向 B，分离 B 的位移为 `+normal*depth`；A 受到负法向冲量。**
包含/同心时按确定性出口规则选择 MTV；对两个不同对象，即使完全重合，
交换参数也严格反转法向、保留深度和点集。MTV 不唯一时用对象身份固定次序；
同一个对象与自身碰撞不具有“非零法向同时等于其负值”的定义，不应加入世界两次。

盒子流形包括 A 的 16 个顶点中位于 B 内部的点、B 在 A 内部的顶点，
加上平移至 MTV 边界后由 GJK 求出的最深支撑特征点。
最后投影到两侧支撑平面的中间超平面并去重。即使交叉细盒没有任何内部顶点，也有特征回退点。
顶点保留采用尺度相关 `1e-7` 接触余量，防止近静止时舍入量级的旋转令整片支撑胞突然退化为一个角点；
此余量不改变 SAT 的精确几何深度。没有做完整四维多胞体裁剪，因此这仍是**近似流形**。

`points` 是双方**共同的世界作用点**。不能让两侧分别在各自穿透表面施力：
两侧冲量即使等大反向，若作用点不同，摩擦冲量也会凭空产生总力矩。
此处 `r_A=p−x_A`、`r_B=p−x_B`，有效逆质量为两侧已验证 `effectiveMass` 的和。
于是冲量交换满足

```
Σ m v 不变
Σ [ L_spin_world + x ∧ (m v) ] 不变（六个分量）
```

### 同一求解器、世界接线与稳定性

未修改 bivector、6×6 惯性、`RigidBody4.step()` 或地板几何/落地过零算法。
只把原地板累计冲量循环提取为 `Physics4.solveContacts`，允许额外的另一刚体、任意法向和恢复目标；
单地板仍走原来的 32 轮和原恢复策略，17 项原测试保持原样。
`World4.step()` 保留原来的逐体积分与地板处理，末尾把**所有双体及地板支撑**放入同一累计求解循环，
不是先解完每对就不再顾及地板。`new World4({ gravity: 0, floor: false })` 可隔离验证无外力的双体冲量。

无摩擦时，双体接触目标是 `v_n_after = −e v_n_before`，迭代允许撤销过量法向冲量。
互补条件 `λᵀ(Kλ+(1+e)u)=0` 给出
`ΔT = −(1−e)/(2(1+e)) λᵀKλ`：
e=1 动能守恒，0≤e<1 不增，不能逐顶点独立反弹后再把过量能量缩掉。
有摩擦时先完成恢复，再使用同一个循环解零目标支撑与三维切空间的库仑摩擦；
恢复冲量作为摩擦预算保留，避免同时强求“恢复后的角向分离速度”和“静摩擦零滑动”。
双体摩擦的投影梯度步长用切向响应矩阵的 trace 上界限制；
沿瞬时滑动方向的 Rayleigh 步长在各向异性接触的库仑球边界上可能形成二周期振荡，不能直接照搬。
双体共享循环最多 2048 轮，静置 e=0 时按接触点一一匹配热启动；不缓存弹性恢复冲量。
没有能量归一化、冻结角速度或睡眠来掩盖不稳定。

宽相位用四维包围球。位置修正沿 MTV 按逆质量分摊，不修改速度；
双体修正保持质心和均匀重力下两体势能总和。地板与双体位置约束迭代消除残余重叠，
该过程中姿态不变，因此缓存 SAT 投影和地板支撑偏移。
位置迭代后残余深度超过 `1e-8`，或冲量迭代后单轮变化超过 `1e-9`，会明确报错。
渲染仍是原 N 体 uniforms/SDF 路径，
默认六体场景含迎面运动的盒子、超球和底座，第四维运动会改变可见切片。

## 十、下一步可以做什么

- **碰撞的下一步**：连续碰撞检测、更完整的接触流形与复杂斜向堆叠；只有增加任意凸体穿透时才需要考虑 4D EPA。

- **双目立体 / WebXR**：给切片视图加真实双目视差。有趣的是四维生物的视网膜是三维的，所以严格说 VR 也只是在演示三维切片。
