# 在浏览器里展示四维空间

第四个维度是**空间维**（记作 w），不是时间。目标是通过可控投影和切片观察四维几何，而不是把二维画面当成完整四维视觉。

## 一、核心难题

屏幕是二维的，本项目选择 4D→3D→2D 两级显示流水线（也可以直接映射到二维）。
一般四维对象的这种连续几何投影会丢信息，问题是**丢哪部分**；这不排除另存坐标或用额外编码保留数据：

| 做法 | 丢掉的是 | 留下的是 | 代价 |
|---|---|---|---|
| **投影** 4D→3D→2D | 一般不能保尺寸、角度或拓扑 | 全体顶点与棱的像 | 重影、交叉和降秩可能掩盖原结构 |
| **切片** 只取一个 3D 超平面 | 超平面外的一切 | 理想截面内的欧氏几何 | 屏幕仍作透视，数值渲染有容差；一次只看到一层 |
| **编码** 把 w 映射到颜色/大小/时间 | 精确的空间关系 | 定量可读 | 不产生空间直觉 |

本项目采用**投影看全貌 + 切片建直觉 + 编码补细节**的分工。这是尚未经用户实验验证的教学设计，不是唯一有效方法或效果保证。

## 二、四维旋转：和 3D 最不一样的地方

**3D 的旋转有不动轴；4D 的简单旋转固定一个平面。双旋转的两个平面转角都不是整周时，没有非零固定向量；原点始终固定。**

四个坐标轴两两配对，得到 6 个旋转平面，所以 SO(4) 有 6 个自由度（SO(3) 只有 3 个）。每个平面对应一个 Givens 旋转矩阵 —— 对平面 (i, j)：

```
M[i][i] =  cos θ    M[i][j] = -sin θ
M[j][i] =  sin θ    M[j][j] =  cos θ
其余为单位矩阵
```

实现见 `js/m4.js` 的 `rotation(plane, angle)`。

把 6 个平面分成两组，是理解四维旋转的关键：

- **xy / xz / yz** —— 不动的平面里含有 w 轴，所以 w 坐标全程不变。这是我们熟悉的「普通 3D 旋转」，投影图上看不出任何异样。
- **xw / yw / zw** —— 混合 w 与相应可见坐标；当 `sin θ≠0` 时，不再保持每个点的 w。可逐个动这三个滑块观察截面/投影变化；旋转对称物体不一定出现形变的视觉效果。

还有一个 3D 里根本不存在的现象：**等倾双旋转（isoclinic rotation）**。两个互相垂直的平面（比如 xy 和 zw）以同一角速度转动，此时：

- 非整周转角没有非零固定向量；原点仍然不动；
- 空间里每一个非零向量都以同一角度转过；
- 四元数乘法就是这件事 —— 左乘单位四元数 = S³ 上的一个等倾旋转。

`index.html` 投影页签的「等倾双旋转」按钮保留当前姿态 `R₀`，重置增量角，
随后使用 `R(t)=Rxy(.4t)Rzw(.4t)R₀`。因此 `R(t+dt)R(t)ᵀ` 始终等倾，
不会因旧的 xw 等角夹在两个变化因子之间而破坏运动。

⚠️ **4D 旋转不交换**，合成 6 个平面时的顺序会影响结果。代码里固定了一个顺序，只求视觉连续，没有物理含义。

⚠️ 另外：连续累乘旋转矩阵会有浮点漂移。`M4.orthonormalize()` 对非退化列做 Gram-Schmidt，
将正交误差压回浮点舍入尺度，不承诺精确归零；`SliceView.frame()` 使用它构造相机标架。

## 三、手法 A：投影（`js/view-projection.js`）

### 4D → 3D

**透视投影**。观察者站在第四维上的 `(0,0,0,d)`：

```js
k = d / (d - w)
(x, y, z) → (x·k, y·k, z·k)
```

这就是超立方体那张「盒中盒」经典图的来源 —— 内层那个小立方体并没有更小，它只是在第四维上离我们更远。`d` 越接近物体（滑块调到 1.3 附近），透视越夸张。

**正交投影**：直接丢掉 w。一般不保长度、角度或拓扑，沿 w 的线段会压成点，也会自我重叠。

**立体投影（stereographic）**：这里使用 S³ 去掉北极后的图，从北极投影到 `w=0` 超平面。

```js
(x, y, z) → (x, y, z) / (1 - w)
```

它在定义域内保角（共形）；本项目选择用它展示 Hopf 纤维化和 Clifford 环面，并非唯一可用的投影。
`M4.stereo4to3` 在 `|1-w|<1e-4` 时钳制分母，该区域不再是精确立体投影；
`ProjectionView.draw` 还做径向归一化、缩放及长棱剔除。因此线框提供整体参考，不保证全体棱都在画面内可见。

### 3D → 2D

普通的可拖动透视相机。**两级投影必须让用户分别控制** —— 否则人分不清「形状在变」和「我在转」。

### 感知技巧（真正决定能不能看懂）

1. **色相编码 w**：暖色 = w 大，冷色 = w 小。没有这个，线框就是一团面条。
2. **线宽随 w 变化**：给一个第二重冗余线索。
3. **按深度排序后绘制**，近处的线更亮更实。
4. **一次只动一个平面**。同时转 6 个平面等于什么都没展示。

### 图形清单

正则四维多胞体一共只有 6 个（3D 是 5 个柏拉图立体）。代码实现了前四个：

| 图形 | 顶点/棱 | 说明 |
|---|---|---|
| 5-cell 单纯形 | 5 / 10 | 四面体的四维版，最简单的四维体 |
| 8-cell 超立方体 | 16 / 32 | 8 个立方体胞，24 个正方形面 |
| 16-cell | 8 / 24 | 超立方体的对偶 |
| 24-cell | 24 / 96 | **四维独有**，3D 里没有任何类比，且自对偶 |
| 6×6 双棱柱 | 36 / 72 | 两个六边形的笛卡尔积；xy 转一个圈、zw 转另一个，互不干扰 |
| Clifford 环面 | — | 把 S³ 干净地分成两个全等实心环 |
| Hopf 纤维化 | — | S² 上每个点对应 S³ 里一整个圆；不含投影极点的纤维在精确立体投影后两两套扣且不相交，有限折线显示只是近似 |

120-cell（600 顶点 / 1200 棱）和 600-cell 没做：线框画出来只是一团毛球，教学价值反而低于 24-cell。

棱表是自动生成的 —— 取所有「距离最短的顶点对」。正则多胞体的最短顶点间距就是棱长，省掉手写棱表。见 `polytopes.js:edgesByNearest`。

## 四、手法 B：切片（`js/view-slice.js`）—— 第一人称观察所选截面

### 原理

思路完全照搬《平面国》：二维生物看不到球，只能看到球与它所在平面的交 —— 一个会长大又缩小的圆。每个词加一维：

> 本项目约定显示四维物体与相机所选**三维超平面**的交，再把该截面投到二维屏幕。这不是人类视网膜的维数描述。

### 渲染管线

1. 玩家在 4D 里有位置 `uCam` 和一组正交基 `(Ax, Ay, Az, Aw)`。前三个张成「我们能看见的那个三维世界」，**`Aw` 指向我们看不见的方向**。
2. 在这个三维切片里做普通的 ray marching。屏幕每个像素发一条射线，射线上的三维点 `q` 先抬回四维：

   ```glsl
   vec4 lift(vec3 q){ return uCam + q.x*uAx + q.y*uAy + q.z*uAz; }
   ```

   然后求**四维**有向距离场 `map(lift(q))`。
3. 法线取 `map` 在 `Ax / Ay / Az` 三个方向上的差分 —— 得到的是**切片内**的法线，也就是切片里的居民真正会看到的明暗。

理想求交不改变截面内部的欧氏距离，但屏幕透视不保长度或角度。
实际 `SliceView` 使用有限步 ray marching：最多 128 步、命中容差 `0.0018·max(t,1)`、
推进系数 0.92、远距 70；法线也用有限差分。小于容差的缝隙、薄物体和近切射线可能误命中或漏检，
不是百分之百精确的几何测量。

### 常用 4D SDF 原语

```glsl
float sdSphere4(vec4 p, float r){ return length(p) - r; }             // glome 超球

float sdBox4(vec4 p, vec4 b){                                         // 四维盒子
  vec4 d = abs(p) - b;
  return length(max(d, 0.0)) + min(max(max(d.x,d.y), max(d.z,d.w)), 0.0);
}

float sdDuocylinder(vec4 p, float r1, float r2){                      // 双圆柱：四维独有
  vec2 d = vec2(length(p.xy) - r1, length(p.zw) - r2);
  return min(max(d.x, d.y), 0.0) + length(max(d, 0.0));
}

float sdSpheritorus(vec4 p, float R, float r){                        // 球环面
  return length(vec2(length(p.xyz) - R, p.w)) - r;
}

float sdTiger(vec4 p, float R1, float R2, float r){                    // 切片会分裂成两个环
  return length(vec2(length(p.xy) - R1, length(p.zw) - R2)) - r;
}
```

注意 `sdBox4` 就是 3D 版本逐字加一维 —— 大部分 SDF 都是这样平移过去的，这也是 SDF 比多边形网格适合四维的原因（4D 三角网格要处理 5-cell 单纯形和四维凸包，工程量高一个量级）。

### 让人不迷失的三个设计

一次只看一层可能难以定位；本项目选择三个定向参照，效果尚未经用户实验验证：

1. **地板棋盘格的第三个因子取 `floor(w)`** —— 沿第四维移动时格子会翻色。这是「我确实动了」最直接的反馈，没有它玩家会怀疑按键失灵。
2. **贯穿所有 w 的柱子** —— 提供「这个方向确实没变」的参照物。
3. **把 4D 转身限制在不含 y 的平面（xw / zw）** —— 地板法线 `(0,1,0,0)` 在这两个旋转下不变，所以转身不会让地板倾斜。若允许 yw 转身，切片中的重力投影方向也会改变；是否导致眩晕需用户实验，不能直接断言。

### 两个额外的可视化开关

- **第四维厚度染色**：命中点沿 `Aw` 正反各探 10 步，数有多少步还在物体内部。薄得像纸（马上要消失）的表面染红 —— 提前告诉你「再按一下 E 它就没了」。
- **X 光**：射线在第四维上左右各偏 `1.1` 再测一次距离，把「隔壁切片里有东西」画成蓝雾。隐藏物体会先以雾的形式出现。

### 场景里安排的教学点

| 物体 | 在第四维上的范围 | 现象 |
|---|---|---|
| glome 超球 | w ∈ [−1.45, 1.45] | 未转身的平行切片半径为 `sqrt(1.45²−w²)`；端点为点，范围外为空 |
| 超立方体 | w ∈ [−1.1, 1.1] | 未转身时为恒定立方体（含端点），范围外为空；斜切不保证立方体 |
| 双圆柱 | w ∈ [−1.15, 1.15] | 未转身时为半径 1.15、半高 `sqrt(1.15²−w²)` 的实心圆柱，端点退化为圆盘；任何仿射截面都凸，不会有环洞 |
| 球环面 | w ∈ [−.45, .45] | 未转身只扫 w 时为同心球壳，内外半径 `1.15 ∓ sqrt(.45²−w²)`；端点退化为球面，范围外为空 |
| tiger | w ∈ [−1.34, 1.34] | 未转身且 w=0 时为 z 正负两侧的两个互不连通实心环面；不是所有切面都保持两个环 |
| 灰墙 | \|w\| ≤ 1.6 | w=0 时真实挡路；碰撞还包含相机半径 |
| 金色方块 | w ≈ 3 | 墙后面，只在那一层存在 |
| 柱子 | 全部 | 参照物 |

**核心体验**：在③中先按 `D` 走到 x≈2，避开正前方的黄色双圆柱，再按 `W` 撞到灰墙 →
按 `E` 把 w 推到 3 → 墙消失且不再挡路 → 走过去并向 x=0 看金色方块。
⑤已经把相机放在墙前，且没有前排展品，可以直接做这组对照。

球环面要看环面截面，需**改变切面方向**，不能只扫 w。例如 `a_zw=π/2`（Z/X 控制 zw 转身）
且相机 `z=-10` 时，`H` 是穿过物体中心的 `z=-10` 超平面：
`(sqrt((x-4)²+(y-.3)²)-1.15)²+w²≤.45²`，这是实心环面。
一个无遮挡的相机状态是 `cam=(4,.3,-10,3), yaw=pitch=a_xw=0, a_zw=π/2`，向 −w 看；
该状态可由 `SliceView.cam/a_zw` 精确设置，现有按键是连续调角，没有 π/2 吸附按钮。
上述几何直接来自 `Scene4.types.duocylinder/spheritorus/tiger` 的 SDF 和 `Scene4.gallery` 参数；
`SliceView.frame` 决定 H，`step` 的 Q/E 只平移世界 w。

灰墙是有限物体，不是封闭牢房。它只证明**原方向被挡时，沿额外方向存在另一条路**；
即使固定 w=0，也可以绕过墙边或让相机中心升到 y>2.85 后越过墙顶。
本项目没有测量这种交互的教学效果，更没有证据支持“理解深度差一个量级”。

### 共享场景与相机碰撞（`js/scene4.js`）

旧版只有地板高度钳制，w=0 也能直接穿过灰墙；上述“先撞墙”的教学对照在旧实现里并不成立。
现在 `Scene4.gallery` 是静态展厅的唯一事实来源：每个对象包含
`{id, type, center, params, material}`。`Scene4.create(objects, true)` 同时产生：

- `map`：可直接注入 `SliceView` 的 GLSL `map(vec4)`；
- `sdf(p)` / `sample(p)`：CPU 距离以及最近物体身份；
- `move(p, displacement, radius)`：静态场景中的四维扫掠与滑动；
- `raycast(p, direction)`：与切片准星相同的射线、步数和命中阈值，返回世界点、物体 ID 与材料局部坐标。

不仅物体列表不再手抄，**图元公式本身也是同一棵小型表达式树**：CPU 求值与 GLSL helper 生成都消费它。
盒子、球、双圆柱、球环面、tiger、柱子和地板均在协议中；对象参数作深拷贝并冻结，
修改场景要重新 `create`，不能只改 CPU 数组而留下旧 shader。
柱子的封顶角距离也改成乘积体的欧氏距离，而不是原来的 `max` 近似；几何零等值面不变。
图元在光滑处满足 `|∇f|=1`；并集用 `min`，接缝/中轴处不可微，重叠内部不承诺到并集边界的精确负距离。
碰撞从外部使用距离，因此不依赖这个内部性质。

相机是**半径 0.35 的四维球**，不是无厚度点，也不是只在当前切片中有体积的三维球：

1. 沿整段请求位移做保守推进，不只检查终点，所以大 dt 不能越过薄墙。凸图元使用最近点支撑平面界，
   非凸环面使用 1-Lipschitz 距离界；不会把凸体的快捷判定套到凹形状上。
2. 首次接触后把剩余位移投影到接触平面的公共切空间：单墙保留切向移动，墙角保留公共切向自由度。
   半径之外留约 `1e-6` 数值间隙；非凸掠射使用至多约 `2e-6` 的接触带，避免无穷趋近。
   凹口的多次接触采用保守平面约束，可能比理想的连续曲面滑动更黏，不模拟玩家动力学或重力。
   外部调用若给出恰好接触非凸表面的初始位置，先做可验证的微小分离；若邻近物体连此间隙都不允许，
   明确报错，不把相机推入另一个物体。正常漫游会自行保留间隙。
3. WASD、升降、Q/E、转身后的行走、w 滑块和 `resetW()` 都经过同一个移动入口。
   滑块显示**实际到达的 w**，不能把相机传送进实体；“回到原点/墙前”则重置到已知安全位置。
4. w=0 时从 `(0,0.4,-15,0)` 向 −z 请求移动 4，只能走约 1.35；
   w=3 时同一操作精确移动 4。灰墙本体到 `|w|=1.6`，但有半径的相机中心要到约 `|w|≥1.95`
   才能完全离开它的碰撞范围；“画面没墙”不等于离墙已超过相机半径。

碰撞**按场景显式启用**，自定义场景默认关闭。`PhysicsView` 仍注入自己的动态刚体 `map`/uniforms，
明确设 `collision: false`，只复用生成的基础图元 helper；保留原相机地板钳制，不与动态刚体碰撞。
这里没有修改 `physics4.js` / `collide4.js` 的动力学或刚体碰撞算法。

| 键 | 作用 |
|---|---|
| 点击画面 | 锁定鼠标，之后移动鼠标转头 |
| `W A S D` | 在三维里走 |
| `Space` / `C` | 上 / 下 |
| **`Q` / `E`** | **沿第四维平移（kata / ana）** |

### A08 联动实验（`js/view-linked.js`）

⑤的两块画布同时使用 `Scene4.linked`：它从展厅对象列表按 ID 取出**灰墙、金块、地板**，不再复制尺寸和位置。
独立协调器持有唯一的 `SliceView` 相机 `c/F`，每帧由同一快照生成概览；并非同步两套相机角度。
宽屏左右并排，小于等于 640px 时上下排列。

- **整体与截面**：淡线是两个四维盒体各自的 16 顶点 / 32 棱；亮线是物体与
  `H={(p−c)·Aw=0}` 的精确交。逐个二维面求交，处理平行、共面、相切，并对点和边去重；
  完整截面不裁剪到取样窗口内，包括第一人称中被遮挡的部分。
- **相机所在超平面**：青色虚线体框沿 `Ax/Ay/Az` 有三个非零跨度，是 H 的有限**三维**取样窗口，
  不是二维薄片。白点与四根标轴显示 c、朝向及法向 Aw。走动时白点和窗口随动，
  改 w 或四维转身时重新求交；在 H 内平移不会假装把整个无限超平面换成了另一张。
- **同一物体/材料点**：下拉选择 wall/treasure，同时强调概览截面和第一人称表面边光。
  右侧准星命中返回对象 ID 与局部材料坐标，左侧粉点直接投影该四维世界点；不做最近像素猜配。
  CPU 准星使用与 shader 相同的 ray-marching 阈值，不宣称是无限精度拾取。
- **先预测再揭示**：先选物体与下一层 w，按“会/不会”预测是否存在截面，再移动并显示答案。
  若碰撞阻止到达目标层，明确报告“未到达”，不把当前位置算作目标结果。
  平时仍可直接 Q/E 或拖当前 w，预测不是导航的强制门槛。

**有意做的减法**：联动不搬整个曲面展厅，也不加入动态刚体。盒体截面能精确构造；
球环面/tiger 在任意倾斜 H 下需要另一套曲面离散与拓扑处理，粗采样线框会误导“同一对象”的对应，
也会让画面拥挤。无限地板保留在第一人称和碰撞场景中，概览明确省略，不把任意有限盒子冒充地板全貌。
没有任意 SO(4) 对象变换协议、双向鼠标拾取或表面网格导出；现有平移/图元参数足以精确表示这组静态实验。
没有概览自转，拖动只改变第二级三维观察相机；固定第一级 xw 投影让不同 w 不至于完全重影。
概览只是投影，不能拿屏幕长度当四维距离；极远处超出投影近裁剪范围的相机标记会被省略。

## 五、手法 C：降维类比（`js/view-analogy.js`）

这里的教学假说是**先把同一套操作在低一维上做一遍**有助于理解；尚无用户实验比较其效果。四块面板：

- **A** 我们的视角：立方体全貌 + 那张切割平面（我们看得见全貌）
- **B** 平面人的视角：他只看到那个多边形 —— 边数会从 3 跳到 4、5、6 再跳回去，他会说「这东西在变形」，但立方体什么都没变
- **C** 同一个操作升一维：超立方体 ∩ 超平面 `w=k` → 一个三维多面体
- **D** 胶片：固定同一材料姿态，在 `[-1.7,1.7]` 抽取七个 k。**七张是样本，不是全部连续截面，也不保证覆盖物体全部范围。**

### 多胞体截面算法

比 marching cubes 简单得多，而且是精确的：

> 用超平面切每个**凸平面面片**。一般相交得到线段，相切可只得到一个点，共面则保留该面的边界；空交不产生几何。先去重，再构成截面线框。

`view-analogy.js:sliceFaces` 与 `LinkedView.section` 共用 `js/section.js`，支持本项目的凸平面面片，不宣称适用于任意非凸或非平面面表。`sliceFaces` 保留线段数组接口，另带去重的 `points` 和 `dimension`（空为 −1），不会把零长线段计为棱。面表自动生成：一个正方形面 = 挑 2 个轴自由变动、另 2 个轴取定值，所以超立方体有 C(4,2)×4 = 24 个正方形面。

已验证的结果：

| 切法 | 得到 |
|---|---|
| 立方体 ∩ `y=0.5` | 正方形（4 条边）|
| 立方体（体对角线竖直）∩ `y=0` | **正六边形**（6 条边）|
| 超立方体 ∩ `w=0` | 立方体（12 条棱）|
| 超立方体 ∩ `w=2` | 空（整个在超平面之外）|
| 超立方体斜切 | 15 棱 / 10 顶点 / 全部度数 3 → 五棱柱拓扑 |

## 六、技术栈怎么选

| 方案 | 适合 | 不适合 |
|---|---|---|
| **Canvas 2D** | 线框投影。几百条棱轻松跑满 60fps，深度排序、色相编码、线宽全都好控制 | 实体表面 |
| **WebGL fragment shader + 4D SDF raymarching** | 切片法。**强烈推荐** —— 一个 SDF 函数搞定整个四维场景，不需要任何网格数据结构 | 大规模场景（SDF 不好做剔除）|
| **three.js + 自写 4D 层** | 想要 PBR、阴影贴图、后处理，或者要和已有 3D 项目整合 | 只做线框时纯属过度设计 |
| **4D marching cubes / 5-cell 网格** | 需要把切片导出成真实 mesh（比如导出 STL 打印）| 实时渲染。每帧重建网格，不如直接 raymarch |

本仓库选了 Canvas 2D（类比、投影）+ 裸 WebGL（切片、物理），因为要保证**零依赖 + `file://` 双击可跑**。所以 JS 都用传统 `<script>` 标签而非 ES module —— `file://` 下 ES module 会被 CORS 拦住。

### 两个容易踩的坑

1. **GLSL 源码必须是纯 ASCII。** GLSL ES 规定的字符集不含中文，ANGLE 等实现会连**注释里**的非 ASCII 字符一起报错。所以 `view-slice.js` 把着色器的中文说明全搬到了 JS 注释里。
2. **不要对向量用三目运算符**（`cond ? vecA : vecB`）。规范允许，但部分老驱动编译不过。写成 `if` 返回。

### 性能

切片与物理视图是逐像素 ray marching，每像素要求几十次四维距离场。按 `devicePixelRatio` 全分辨率渲染在集显上会掉到个位数帧率，所以 `app.js` 给它们设了 `Math.min(dpr, 1)`；线框那两个视图是 Canvas 2D，反而需要高 dpr 才不毛糙。
主射线预算集中在 `Scene4.ray`，软阴影步数（28）仍在 `FRAG`；调整主射线预算会同时影响 CPU 拾取和 GPU 命中，必须重新运行语义回归。

## 七、四维刚体物理（`js/physics4.js`、`js/view-physics.js`）

### 为什么角速度不再是向量

任意维度的角速度实际都是反对称矩阵 Ω，或等价的 **bivector（二重向量）**。
三维恰好 C(3,2)=3，可以通过 Hodge 对偶写成「转轴向量」；四维 C(4,2)=6，不能再用一个四维向量冒充。
本实现和 `M4.PLANES` 统一使用 **`[xy, xz, xw, yz, yw, zw]`**，每个分量对应一个旋转平面，而不是一根转轴。
原来的平面表将 yz 放在 xw 前面，这里已统一；现有投影动画仍保留自身的合成顺序，函数签名没有改变。

正 xy 分量把 +x 转向 +y，和 `M4.rotation('xy', angle)` 同号：

```
Ω[i,j] = -ω_ij，Ω[j,i] = ω_ij
(a ∧ b)_ij = a_i b_j - a_j b_i
τ = r ∧ F，v_contact = v_center + Ω_world r
```

这个约定满足 `〈r∧F, ω〉 = F·(Ωr)`，保证转动能、力矩与接触冲量的符号一致。
姿态 R 把本体系送到世界系；bivector 的换系是 `B_world = R B_body Rᵀ`，
**不是**把它当成四维向量乘一次 R。`Physics4.dot6` 是六分量内积，不能用只读四分量的 `M4.dot` 代替。

### 6×6 惯性张量从哪里来

把 `T_rot = ½∫|Ωr|² dm` 展开成关于六个 ω 分量的二次型，得到 `T_rot = ½ωᵀIω`。
I 把 bivector 映到 bivector，因此是 **6×6 对称正定矩阵**。实现支持完整的行主序 36 元素矩阵，
通过 Cholesky 验证正定性并求逆；对齐主方向的两种均匀实心形状有简单解析式：

| 形状 | 二阶矩 | 每个平面 ij 的对角惯性 |
|---|---|---|
| box4，半边长 h | `〈r_i²〉 = h_i²/3` | `m(h_i²+h_j²)/3` |
| glome，半径 a | n 维实心球 `〈r_i²〉 = a²/(n+2)` | n=4 时 `ma²/3` |

交叉二阶矩为零，所以这些主平面基底下非对角项为零。这里的 glome 是**实心四维球**，
不是 S³ 球壳，也不能套三维球的 `2ma²/5`。盒子的 `h_w=0` 可用于三维退化检验。

### 欧拉方程与时间积分

世界系角动量满足 `dL_world/dt = τ_world`。对 `L_body = Rᵀ L_world R` 求导，
结合 `R' = RΩ`，得到

```
I · dω_body/dt = τ_body - [Ω, L_body]
[Ω, L] = ΩL - LΩ
```

无外力矩时，世界系 L 不变，但本体系 ω 通常不断改变，这就是自由刚体的 tumbling。
**并非只有等倾运动才有恒定 ω**：等方惯性（例如 glome）、单主平面旋转等也可以；
关键条件是 `[Ω,Iω]=0`。

平移采用**半隐式欧拉**（先更新速度，再用新速度更新位置），重力沿 −y。
转动先 kick 世界角动量，再以固定的世界 L 积分 `R'=RΩ(RᵀL_world R)`：
使用 RK4，并在每个姿态子步调用 `M4.orthonormalize`，最后从新姿态重新求本体系 ω。
这里刻意没有用裸 Euler 更新 ω：它会持续积累转动能误差，无法满足长时间守恒要求。
世界 L 的保持来自坐标变换恒等式；能量是四阶数值近似守恒，**不做事后能量缩放或自由运动阻尼**。
单步估计转角超过 0.05 弧度时细分姿态积分。外力和外力矩在每个物理步之后清空。

### 地板接触与冲量

地板是 `y = -1.5` 的无限超平面。box4 枚举 16 个顶点，最深穿透量用于直接投影修正；
同时保留接触顶点做多点支撑，避免把平放盒子当成单个角点支撑。glome 用中心到地板的距离。
法向冲量的有效逆质量包含完整的角向项：

```
k(n) = 1/m + n · [I_world⁻¹(r ∧ n)] r
j_n = -(1+e) v_contact·n / k(n)
Δv = J/m，Δω_body = I_body⁻¹[(Rᵀr) ∧ (RᵀJ)]
```

方括号内先得到 bivector，再转成反对称矩阵作用到 r。三维退化时就是熟悉的叉积有效质量公式。
地板的切空间有 x/z/w **三个**方向：摩擦沿接触点滑动速度反向，并限制在 `|J_t| ≤ μJ_n` 的库仑锥内。
反弹逐点处理；随后做至多 32 轮累计支撑/摩擦冲量迭代，允许撤回过量支撑。
法向接近速度小于 0.5 时不触发恢复反弹，以免静止物体因每一步重力 kick 微跳。
位置修正与速度求解分开，不把穿透深度变成额外弹射速度。
对步首悬空、步末穿透的情况，在半隐式轨迹上二分首次检测到的落地过零并拆分该时间步，
避免完全弹性落体因整步穿透后抬高位置而越弹越高；外力在拆分的两段中按各自时长施加。

## 八、四维两两碰撞（`js/collide4.js`）

### GJK 如何升到四维

支撑函数仍是 `s(d) = argmax x·d`。box4 先把 d 乘 Rᵀ，本体系取 `sign(d_i) h_i`，
再乘 R 加质心；glome 返回 `x + radius·d/|d|`。Minkowski 差的支撑点是 `s_A(d)-s_B(-d)`，
每个点同时保存 A、B 的原始支撑点，用重心坐标还原最近点对。
`Collide4.gjk(a,b)` 返回 `{ intersects, distance, pointA, pointB, iterations }`，
也接受提供世界系 `support(direction)` 的任意凸体，不依赖 SAT 或形状专用回退。

四维单纯形最多 **5 点**。最近点例程枚举全部非空子面，最多 31 个，包括 5 个四面体边界胞；
对每个仿射子空间求原点投影，检查重心坐标非负，再选最近的可行面。
这里没有照搬 Johnson，也没有采用 signed-volume 的行列式比值：
选择**二次正交化 QR**，避免 Gram 行列式平方条件数，便于处理降维、共面和长宽比很大的单纯形。
这是常数规模的穷举，不是对形状顶点穷举。近接触时，再消除投影中的切向消减误差，
否则一个约 `1e-16` 的切向残差就可能阻止距离约 `1e-6` 的 GJK 收敛。
距离上、下界之差作为终止条件，尺度相关容差为 `1e-10`；迭代超过 256 次明确报错，不返回假成功。

**GJK 不返回穿透深度。** 零距离只有相交/接触信息，没有 MTV。
因此验证深度时，把 B 沿 SAT 法向分别平移 `depth`、`depth−2e-6`、`depth+2e-6`：
独立 GJK 必须分别报告接触、仍相交、分离且距离为 `2e-6`。
这不是将 SAT 深度回填到 GJK 再比较同一个数。

### 为什么盒子用 SAT，不用四维 EPA

四维 EPA 的边界是**四面体胞**，新顶点的 horizon 是**三角形集合**，
需要维护闭合的三维边界复形；把三维 EPA 的三角形列表直接升维是不正确的。
盒子有更简单而精确的特例：n 维盒子的 Minkowski 差是 zonotope，候选胞法向
由 A、B 棱方向中取 n−1 个张成的超平面得到。四维的候选数为：

| 棱方向组合 | 数量 |
|---|---:|
| 3A：A 自身的胞法向 | 4 |
| 3B：B 自身的胞法向 | 4 |
| 2A+1B | C(4,2)×4 = 24 |
| 1A+2B | 4×C(4,2) = 24 |
| 合计 | **56** |

三个方向的广义叉积为 `n_i = (−1)^i det(删掉第 i 列的 3×3 子阵)`。
忽略线性相关的零轴，其余归一化后，投影半径为 `Σ h_i |R_i·n|`。
任意轴分离就无接触；否则最小的 `r_A+r_B−|(x_B−x_A)·n|` 是精确 MTV 深度，
也正确处理一个盒子完全包含另一个盒子。三维退化时保留 xyz 的胞法向和交叉轴，
相交结论与 15 轴 3D SAT 一致；共同的零厚度 w 轴意味着 **4D 穿透深度为零**，
不能要求它也等于三维内部的穿透深度。

glome/glome 用球心距离；glome/box4 把球心送到盒子本体系逐坐标 clamp。
球心在盒内时，选择最近出口胞面，深度为到该面的距离**加**球半径，而非简单返回半径。

### 接触流形与共同作用点

`Collide4.collide(a,b)` 无接触时返回 `null`，否则返回 `{ normal, depth, points }`。
**normal 从 A 指向 B，分离 B 的位移为 `+normal*depth`；A 受到负法向冲量。**
包含/同心时按确定性出口规则选择 MTV；对两个不同对象，即使完全重合，
交换参数也严格反转法向、保留深度和点集。MTV 不唯一时用对象身份固定次序；
同一个对象与自身碰撞不具有“非零法向同时等于其负值”的定义，不应加入世界两次。

盒子流形包括 A 的 16 个顶点中位于 B 内部的点、B 在 A 内部的顶点，
加上平移至 MTV 边界后由 GJK 求出的最深支撑特征点。
最后投影到两侧支撑平面的中间超平面并去重。即使交叉细盒没有任何内部顶点，也有特征回退点。
顶点保留采用尺度相关 `1e-7` 接触余量，防止近静止时舍入量级的旋转令整片支撑胞突然退化为一个角点；
此余量不改变 SAT 的精确几何深度。没有做完整四维多胞体裁剪，因此这仍是**近似流形**。

`points` 是双方**共同的世界作用点**。不能让两侧分别在各自穿透表面施力：
两侧冲量即使等大反向，若作用点不同，摩擦冲量也会凭空产生总力矩。
此处 `r_A=p−x_A`、`r_B=p−x_B`，有效逆质量为两侧已验证 `effectiveMass` 的和。
于是冲量交换满足

```
Σ m v 不变
Σ [ L_spin_world + x ∧ (m v) ] 不变（六个分量）
```

### 同一求解器、世界接线与稳定性

未修改 bivector、6×6 惯性、`RigidBody4.step()` 或地板几何/落地过零算法。
只把原地板累计冲量循环提取为 `Physics4.solveContacts`，允许额外的另一刚体、任意法向和恢复目标；
单地板仍走原来的 32 轮和原恢复策略，17 项原测试保持原样。
`World4.step()` 保留原来的逐体积分与地板处理，末尾把**所有双体及地板支撑**放入同一累计求解循环，
不是先解完每对就不再顾及地板。`new World4({ gravity: 0, floor: false })` 可隔离验证无外力的双体冲量。

无摩擦时，每轮同时冲击求解 `v_n_after ≥ −e v_n_before`，迭代允许撤销过量法向冲量；
有冲量的活动点满足等号，没有冲量的点只须满足不等式。
互补条件 `λᵀ(Kλ+(1+e)u)=0` 给出
`ΔT = −(1−e)/(2(1+e)) λᵀKλ`：
同一 e 的无外力接触组中，e=1 每轮动能守恒，0≤e<1 每轮不增。
但这个互补条件本身并不保证碰后所有点都分离：初始分离点的恢复目标为负。
因此每轮检查实际 `v_n`，若仍有 `<−1e-10` 的点，就以本轮末速度为新的入射速度，
继续传播同时冲击（最多 64 轮，超出仍报错）。每轮都满足上述能量式，
不是把目标夹到零后冒称守恒，也没有事后能量缩放。摩擦为零和趋近于零时使用同一冲击阶段。
有摩擦时先完成恢复，再使用同一个循环解零目标支撑与三维切空间的库仑摩擦；
恢复冲量作为摩擦预算保留，避免同时强求“恢复后的角向分离速度”和“静摩擦零滑动”。
双体摩擦的投影梯度步长用切向响应矩阵的 trace 上界限制；
沿瞬时滑动方向的 Rayleigh 步长在各向异性接触的库仑球边界上可能形成二周期振荡，不能直接照搬。
静置 e=0 时按接触点一一匹配热启动；不缓存弹性恢复冲量。
求解策略不再只依赖一次 2048 轮预算：

- 几何固定期间缓存 `J` 和 `M⁻¹Jᵀ`。摩擦固定点迭代每 8 轮尝试一次 Anderson 混合，
  最多保留 7 个历史状态；候选先投回合法法向/库仑约束，只有**真实残差下降至少 10%** 才接受，
  否则精确恢复原速度和冲量，继续原来的投影 Gauss–Seidel。
- 每批结束检查整个接触集合的投影固定点残差和法向速度违约，不只看最后一次冲量变化。
  目标统一为 `≤1e-12`，比旧的 `1e-9` 失败阈值更紧。删除摩擦速度 `<1e-10` 时不再更新的截断，
  防止算法自己制造无法达到收敛阈值的平台。
- 仍在收缩的残差允许按批次续解；批次累计上限 32768。停滞或用尽预算抛出
  `ContactConvergenceError`，`World4.step` 恢复**全部刚体、外力/力矩与接触缓存**，
  把该步二分后重试，最多 8 层。外力在两个半步各作用半个 dt，不重复也不丢失。
  重试仍失败则回滚原状态并显式报错；UI 停止受影响页签，允许用户点击复位恢复。

Anderson 只加速原方程，并不提供任意库仑接触的全局收敛证明；
残差验收、有限续解和回滚细分是必要护栏。默认参数扫描不等于任意堆叠可靠性的证明。
没有能量归一化、冻结角速度或睡眠来掩盖不稳定。

宽相位用四维包围球。位置修正沿 MTV 按逆质量分摊，不修改速度；
双体修正保持质心和均匀重力下两体势能总和。地板与双体位置约束迭代消除残余重叠，
该过程中姿态不变，因此缓存 SAT 投影和地板支撑偏移。
位置迭代后残余深度超过 `1e-8`，或接触残差在有界重试后仍超过 `1e-12`，会明确报错。
渲染仍是原 N 体 uniforms/SDF 路径，
默认六体场景含迎面运动的盒子、超球和底座，第四维运动会改变可见切片。

  随机碰撞及扫描还检查 `v_n≥−1e-10`，不再只凭守恒量判断响应。
  上面的“本轮环境没有浏览器”描述的是旧实现阶段；当前真浏览器覆盖见 `tools/verify-render.js`。

**没有实现 EPA、任意凸体穿透求解、完整接触裁剪、完整 CCD、关节和通用可靠堆叠。**
四盒平放堆叠通过严格静置测试，不代表任意斜盒、多层高塔或极端质量比也已验证。
深度来自精确 SAT/解析式，但流形和有限步长轨迹不是精确解。
**最可能出问题的是近退化特征切换、复杂斜向堆叠及高速穿越**：
离散检测可能完全漏掉一个时间步内穿过的物体，深穿透的平移修正也会改变
`x∧mv`，所以冲量交换的角动量守恒不等于深穿透修正后的完整轨迹守恒。
地板抬升及多体深穿透也可能改变机械能，不能把无重力压力测试扩张为所有重力场景的证明。
这些边界没有靠放宽守恒断言或事后缩放速度处理。

## 九、手性翻转（`js/chirality4.js`、`js/view-chirality.js`）

第⑥页签把 [A01](docs/intuition-research.md#a01-手性翻转首选但必须是有厚度有身份的手) 与
[独立原型](proto/chirality.html) 接成可核对的对照实验。十块有厚度的积木组成同一个刚体，
掌心一颗红标、手背两颗蓝标，所有面颜色及材料 ID 固定。没有贴图翻转、缩放、关节动作或形变。
先拖左侧 xy/xz/yz 三个角，试着匹配蓝色虚线右手；再把四维角推到 90°、180°。
两个主图共用固定尺度与三维观察相机；改变相机不改变任何分数。
也可直接拖动三维画面，或在四维画面横拖从 0° 走到 180°；小屏上下排列，触屏纵向滚页，
顶部不变量在画布区域内保持可见。切换页签或窗口失焦会暂停播放并清除拖动状态。

**失配定义**：掌心 P、手背 D、腕 W、五个指尖 T/I/M/R/L、掌缘 A/B 共 10 个具名材料点，
目标 `qᵢ = (−pᵢ.x, pᵢ.y, pᵢ.z, 0)` 在初始化后冻结。两组先对齐材料点质心。
令 `L = 初始 |AB| = 1.2`，屏幕显示
`e = sqrt(Σᵢ ||R pᵢ − qᵢ||₄² / 10) / L` 的百分数；这是距离比，不是相似度概率。
不交换编号、不以最近点或轮廓配对，也不丢弃 w。逐点表显示每项距离 / L。
质心对齐已经采用最优平移；再平移 t 只会给 `e²` 增加 `||t||²/L²`，不是故意限制平移来制造失败。

**三维下界不是随机搜索猜出来的**：记中心化材料点协方差为 `C = Σ pᵢpᵢᵀ / 10`。
对镜像 M 与任意 `R∈SO(3)`，`Q=MᵀR` 的行列式为 −1，故 `tr(Q)≤1`；
若 `C≥λI`，则 `e²L² = tr((Q−I)C(Q−I)ᵀ) ≥ 4λ`。
代码用对称矩阵的行对角占优界计算 λ。本例掌背对称使 z 与 x/y 不相关，
最小特征值恰为 `λ=0.01152`，因此 **e≥0.17888543819998318（17.888544%）**。
“三维最佳姿态”绕 xz 转 π，恰好达到这个下界；此时轮廓很像，但掌背点各错开 0.48。
这展示的是整个 SO(3) 的限制，不是三个单轴失败样本。

**90° 不压扁**：两组投影固定为 xyz 与 yzw（后者横轴是 w），始终读取同一组四维坐标，
不自动转观察基、也不切换模型。旁边 A/B 的 xw 圆弧记录显示 Δx 从 1.2 降至 0 时，
Δw 正好增至 1.2。屏幕常驻、逐帧从实际坐标计算：

- `|AB|₄ = 1.2`；
- A/B/W/P 材料四面体的 `sqrt(det(BᵀB))/6 = 0.048`（不是整只手的总体积）；
- xyz 定向体积比 `Vxyz/V0 = cosθ`，90° 时为 0；
- 当前矩阵的 `det(R₄)=+1`，并显示上述不变量的原始浮点漂移。

**没有对运动物体执行镜像**：每帧直接从原坐标应用 `M4.rotation('xw', θ)`，
不累乘上一帧姿态。终点 `diag(−1,1,1,−1)` 同时反转 x 和 w，四维行列式仍为 +1；
只有限制到 `w=0` 超平面时，才是三维行列式 −1 的反射。静态目标当然预先作了镜像，
这与运动路径有意分离。180° 的非零分数按科学计数法保留 `sin(π)` 的机器精度残差，
不把小于某个人为阈值的误差改写成 0。

**验证**：`node test/chirality4.test.js` 用 2,177 个角度检查 80 个网格顶点和 10 个标号点的
全部 4,005 对距离；独立余子式行列式、Gram 矩阵及 Cauchy–Binet 子式平方和核对体积。
端点 xyz 逐分量精确等于镜像，w 误差限制为 `Number.EPSILON × |初始 x|`。
60,000 个固定种子、均匀单位四元数旋转加八组局部优化，核对非零下界，
同时要求四维终点失配不超过机器 epsilon。测试也覆盖实际视图的度量及播放终点；
`scene4.test.js` 的主站替身补充了第六页签的按钮、暂停与切页接线。

**显示边界**：仍是二维屏幕上的投影，不是真实四维视觉或 w=0 截面。
标号穿透遮挡显示，背面的点也可追踪；重影不代表材料相撞。
Canvas 2D 按面平均深度排序，积木接缝及近退化角度可能有遮挡绘制瑕疵；
不能拿像素重合证明空间重合。最容易引起“偷偷换图”的地方仍是 90° 附近的薄片和
三维最佳姿态的相似轮廓，因此固定补图、逐点表、不变量与完整矩阵都可随时核对。
此处证明三维手性物体借第四维翻转，不声称一般四维手性物体也能在 SO(4) 内变成镜像。

## 十、刚性双环分离（`js/rings4.js`、`js/view-rings.js`）

第⑦页签直接使用 [研究 A02](docs/intuition-research.md) 的两只半径 1 的刚性圆环：

```text
A(u) = (cos u, sin u, 0, 0)
B(v) = (1 + cos v + x, 0, sin v, w),  0 ≤ u,v < 2π
管半径 ρ=0.1；x 表示 B 相对于初态的位移，不是圆心坐标。
```

每环 96 个固定材料点，首尾由显式循环边连接；所有姿态直接从冻结的初始坐标整体平移得到，
不累加顶点漂移、不改形状、不重新配点。`Rings4` 负责路径、最近材料点、逐段胶囊距离和三维接触限制；
`RingsView` 仅负责控制及 Canvas 2D 投影，不接入或修改 `PhysicsView`。
这里的管指中心线的半径 ρ 邻域；四维中其法向截面是三维球，屏幕粗线只是管的投影示意。

### 三段都要走，且全程有解析安全间隔

进度 `t∈[0,3]` 对应三段，每段单位时长；按 A02 实现，不用采样结果决定是否“安全”：

| 段 | B 的整体运动 | 连续中心线距离下界 | 保证的管面间隔 |
|---|---|---|---|
| ① `0≤t≤1` | `x=0, w=t` | `√(1+w²)` | `√(1+w²)−0.2 ≥ 0.8` |
| ② `1≤t≤2` | `w=1, x=3(t−1)` | `1` | `0.8` |
| ③ `2≤t≤3` | `x=3, w=3−t` | `2` | `1.8` |

这些下界对**所有 u、v 和连续时间**成立，故整个运动中的管都不相交，不取决于播放帧率。
段端点可使用相邻任一段的有效下界；界可以跳变，真实距离连续。
页面同时显示当前**精确中心线最小距离**、当前解析下界及两者各自对应的管面间隔。
在这族受限姿态（`c=1+x≥1`）中，A02 的距离平方对 `cos u`、`cos v` 依次最小化，
最近点可始终取 **A(0)、B(π)**，因此 `d₄=√((x−1)²+w²)`；
实际读数从这对四维材料坐标计算，不把保守下界回填成测量值。
初态最近点可能不唯一，选择固定这一对可避免追踪点突然换身份。

同时逐对计算 96×96 条线段的最近距离，相当于闭合胶囊链的管面间隔 `d折线−2ρ`。
圆环非凸，**整个环从未交给凸体 GJK/SAT**。弦与圆弧有差别，
其 Hausdorff 误差为弓高 `s=1−cos(π/96)`；精确圆的距离必落在
`[max(0,d折线−2s), d折线+2s]`。页面明确展示这个独立数值核对区间。
这是当前姿态的几何交叉检查，**不是连续时间证明的替代品**。

### 三维失败与“看着像穿模”的对照

左侧锁定 `w=0`，横拖或滑块请求沿 x 拉开。对这条路径，首次管面接触精确发生在
`x=1−2ρ=0.8`，接触中心线点是 A(0)=(1,0,0,0)、B(π)=(0.8,0,0,0)，
管面接触点为 `(0.9,0,0,0)`。两点与接触位置均高亮。任何请求都先限制到首次接触：
即便直接请求 `x=3`（终点本身无碰撞），也不能跳过中间接触；可向回拉或重置。
淡蓝填充圆盘只是证明用的辅助面，不参与碰撞，真正的接触发生在圆环上。
**这不是任意三维六自由度拖拽物理，也不是遍历所有三维运动；一般不可能性的依据见下一节。**

右侧走完整四维路径，播放第一次经过 **t=4/3、x=1、w=1** 时自动暂停，
“停在投影交点”按钮也可精确定位此时刻。在实数数学中：

```text
A(0) = (1,0,0,0)
B(π) = (1,0,0,1)
dxyz = 0，但 wA=0、wB=1；d₄=1 > 2ρ=0.2，管面间隔 0.8。
```

两幅大图固定丢弃 w，再用相同三维正交相机观察；不会为了遮丑把重影错开。
交点上同时画两个不同大小的标记、分开标注 A(0)/B(π)；
下方 xw 尺用**同一对材料点**直观展示被丢弃的 1 单位 w 间隔，顶部保留数字证据。
普通屏幕交叉可能只是三维相机遮挡，只有 `dxyz=0` 才是真正的 xyz 相交。
浮点实现的 `sin(π)` 与 `3(4/3−1)` 有约 `10⁻¹⁶` 残差；界面六位小数取整显示，测试保留原值。
相机设置不改变任何坐标或距离。

路径下拉框明确提供 **“升 w → 不移 → 降 w”失败模式**：中段停在原来的 xyz，
最终所有材料点逐位回到初态，仍然套扣。它也安全，距离全程为 `√(1+w²)`，
但绝不沿用完整路径第三段 `≥2` 的下界，也不把“升起过”判成成功。
窄屏四图纵排；横拖控制、纵向滚页。切页、失焦、隐藏页面会暂停并清除拖动状态。

### 三维不可能性：有拓扑证明，不只是数值证据

令 A 按 u 增大定向，以 xy 单位圆盘 D 为其定向张成面（法向 +z）。
初始 B 与平面 z=0 只有 `v=0,π` 两个横截点：
`v=0` 给 `(2,0,0)`，在 D 外；`v=π` 给 `(0,0,0)`，在 D 内，
且 `dz/dv=cosπ=−1`。故代数交数、亦即**链环数 Lk(A,B)=−1**。
完整四维路径的终态回到 w=0 后，B 的 x 范围 [3,5] 与 A 的 [−1,1] 被平面分开，
张成圆盘没有交点，**Lk=0**。只升降的终态仍是原来的 −1。

若存在一条保持两条闭曲线不相交的连续三维分离路径，那么
`G_t(u,v)=(A_t(u)−B_t(v))/|A_t(u)−B_t(v)|` 给出从二维环面到 S² 的连续同伦。
其整数度数在同伦中不变；按参数域 `du∧dv` 定向，`Lk=−deg G`
（v 导数引入 `−B′`），所以链环数也不变。初态 −1 不可能变成分开的 0，矛盾。
因此**任意三维平移/旋转组合，甚至允许不相交的柔性变形，都不能解开这对环**；
若强行走向分离，必有中心线相交，而连续距离必先经过管径 0.2，即先发生管面接触。
这证明不依赖左侧的一条试拉路径或有限搜索。

上述论证适用于连续、不相交、有固定身份的光滑/驯服闭曲线；切断、穿透、瞬间传送不在前提内。
四维路径离开共同的三维空间后，Gauss 差向量落在 S³ 而非 S²，故不受这个三维整数约束。
这不是说“约束在 S³ 中的链环也能解开”，也不推广为任意刚性连锁结构都可按此路径分离。
中间四维姿态不标注三维链环数，尤其 xyz 相交时 Gauss 三维积分根本无定义。

### 独立验证

`node test/rings4.test.js` 无框架、无依赖，共 17 项；可加名称子串单独运行。
链环数不调用模块的下界或最小距离，用独立 Gauss 双重求和：

```text
Lk = (1/4π) ∬ ((A(u)−B(v)) · (A′(u) × B′(v))) / |A(u)−B(v)|³ du dv
```

使用圆的解析切向量、带非整格相位的周期梯形求积、Kahan 补偿累加，
在 `64²、128²、256²` 项分别检查收敛；**不先 round 再断言**。
初态 −1、终态 0 的允许误差均为 `64 Number.EPSILON ≈ 1.42e−14`；
反转一个环的定向须得到 +1，共同平移/旋转后仍得到同一整数。
数值积分是独立核对，三维不可能性的证明是上面的交数与同伦不变性。

每环全部 4,560 对材料点在完整/失败两条路径各 1,537 个时刻核对刚体性，
绝对误差限 `8 EPS`；短弦受平移相减舍入影响，另限制相对误差 `64 EPS`。
闭合检查包括每点度数 2、首尾边、所有弦长及路径分段接续；
每段各测 **17,907,712 组 (u,v,t)**（规则密网格及非整格偏移），
对平方距离只允许 `8 EPS` 舍入误差，且始终严格大于 `0.04`。
另测投影真交点、胶囊距离及弓高误差界、精确首次三维接触、不可省的中段、
真实视图的交点暂停/终点/输入隔离，以及错误输入显式报错。
主站 DOM 替身检查三维接触、交点证据、两种路径终点、切页暂停，以及实际返回/显示的下界与管面保证。
真实 Chromium 经 `file://` 核对七页签初始化/绘制和桌面/窄屏布局，包含联动右侧画布及背景/文字负对照。
GPU 射线/动态 SDF 另用 1×1 诊断画布精确读回数值，不把它当作全分辨率 GPU 性能验证。

## 十二、下一步可以做什么

- **碰撞的下一步**：连续碰撞检测、更完整的接触流形与复杂斜向堆叠；只有增加任意凸体穿透时才需要考虑 4D EPA。
- **四维光线追踪**：让光线本身在 4D 里传播（而不是只在切片里），阴影和反射会来自「我们看不见的方向」。
- **把切片渲成真 mesh**：4D marching cubes（在 5-cell 单纯形上做 marching），可以导出 STL 3D 打印一个四维物体的截面序列。
- **120-cell / 600-cell**：用胞着色 + 透明度代替线框，否则只是一团毛球。
- **双目立体 / WebXR**：可给所选三维切片加双目视差；仍不会显示完整四维物体。假想四维观察者的三维成像超平面是数学模型，不是人类视网膜的性质。
